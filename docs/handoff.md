## 2. 项目定位与当前真实状态

**定位**：自用的跨平台主动式个人记录工具（Windows + macOS）。程序长期后台常驻，用户通过全局快捷键随时调起轻量快速记录窗口，主动写下想法/任务/决定/问题/灵感；内容按日期归集，并支持每日 AI 总结与结构化信息提取。

**已明确放弃**：后台被动采集用户在各软件中的输入内容（噪声大、质量不稳定）。**任何情况下不得重新引入被动监听类需求。**

**当前真实状态（截至 2026-10-04）**：

| 项 | 状态 |
|---|---|
| 代码 | 无。没有任何源码、配置文件、依赖清单 |
| 项目初始化 | 未执行。无 `package.json`、`src/`、`src-tauri/`、`README.md`、`AGENTS.md` |
| 依赖与工具链 | 未安装任何项目依赖；本机未安装 Rust 工具链（详见 §6） |
| 唯一已有产物 | `docs/design/tech-plan.md`（技术方案初稿）、`docs/handoff.md`（本文） |
| 设计阶段 | 需求边界、选型、架构、数据模型、Quick Capture、AI 总结、阶段规划已完成一轮讨论并确认 |

## 3. 已锁定决策（不得重新反复争论）

以下为上一轮讨论中用户明确确认的决策，除非用户主动提出变更，否则视为既定前提：

| 决策 | 结论 |
|---|---|
| 桌面框架 | **Tauri 2**（曾对比 Electron，用户最终选择 Tauri 2） |
| 前端 | Vue 3 + TypeScript + Vite |
| 数据库 | SQLite 作为唯一 Source of Truth；通过 `tauri-plugin-sql` 访问；**SQL 与数据语义留在 TypeScript**；不使用 ORM |
| 数据库迁移 | 在 Rust 侧声明 migration |
| AI 请求传输 | 自定义 Rust 薄命令（reqwest），只做"发请求、回内容"；**不使用 `tauri-plugin-http`**（原因见 `tech-plan.md` §3.1） |
| Rust / TS 边界 | **「何时」与「系统」归 Rust，「做什么」与「规则」归 TS**（详见 `tech-plan.md` §4.2） |
| AI 总结触发 | **MVP 仅手动生成**；自动触发与补偿整体后移到阶段 4 |
| macOS 条件 | 用户有 Mac，可本地构建调试 |
| 软删除 | 采用（`deleted_at`） |
| 过期判定 | 内容指纹 `source_revision`，读取时比较，不维护"过期标志" |
| 结构化结果存储 | `daily_summary.payload` JSON 列，不拆多表 |
| 搜索 | MVP 用参数化子串匹配（`LIKE`），不引入 FTS5 |
| Markdown / JSON | 单向派生输出，**绝不回读** |
| 密钥存储 | 优先 `keyring` crate（Windows Credential Manager / macOS Keychain）；成本过高则降级为明文 + 风险提示（阶段 3 定案） |

**不要重新提议**：Electron 迁移、Rust 内 rusqlite 替代方案、AI 自动触发的 MVP 化、ORM 引入、FTS5 提前落地——这些都已在上一轮讨论过并给出了结论或延后安排。

## 4. 需求红线

### 4.1 MVP 必须覆盖

Quick Capture 完整体验（草稿、中文输入、快捷键冲突检测与自定义）；后台常驻体系（托盘/菜单栏、开机自启、单实例、暂停快捷键）；Entry 记录与浏览（今日、历史日期、编辑、删除、复制）；SQLite 持久化与导出备份；基础搜索；每日 AI 总结（手动）；设置页。

### 4.2 明确不做（任何阶段都不得擅自引入）

被动监听键盘/输入法、读取其他应用输入框、Keylogger、浏览器扩展、OCR、截屏识别、云服务、账号、多用户、实时同步、向量数据库、Embedding、RAG、Agent、知识图谱、自动长期记忆、自动人格分析、实时 AI 对话、每条 Entry 实时分类、重型笔记系统层级结构。

### 4.3 需求冲突修正结论（必须遵守）

| # | 结论 |
|---|---|
| 1 | 不追求"不抢焦点"。**快速记录必然短暂抢占焦点，隐藏后归还焦点给原应用**（macOS non-activating panel 会导致无法输入中文，不可采用） |
| 2 | **Esc = 保留草稿并隐藏**，不提供取消语义 |
| 3 | 自动总结**不做"补跑错过的定时任务"**，改为声明式期望状态 + 对账扫描 |
| 4 | 自动总结目标日期问题随"仅手动"暂缓到阶段 4 |
| 5 | 默认快捷键保留（Win `Ctrl+Shift+Space` / macOS `Cmd+Shift+Space`），但**注册失败必须可见**并提供换键入口 |
| 6 | **日期在写入时固化为独立列**，不在读取时动态推导；不做自动重算 |
| 7 | 暂停 = 注销全局快捷键（阶段 4 起追加暂停自动总结） |
| 8 | Markdown / JSON 单向派生输出 |
| 9 | 草稿 MVP 为全局单一 active draft，表结构预留多草稿扩展位 |

## 9. 阶段 1 必须实测的未验证项

以下项在上一轮仅完成静态分析，**不可当作已确认事实**，必须在阶段 1 用真机行为确认：

| # | 待验证项 | 若失败的降级方案 |
|---|---|---|
| 1 | Windows 热键唤醒后能否稳定抢占前台焦点（Tauri 有 `show()` 后 `set_focus()` 失效的公开问题） | 采用 `unminimize()` → `show()` → `set_focus()` 顺序并追加一次聚焦；仍失败则评估调起时重建窗口 |
| 2 | 隐藏创建的 capture 窗口能否可靠收到通知（Tauri 有相关公开问题） | 已设计规避：关键路径不依赖 Tauri 事件通道，改用 DOM `focus` / `visibilitychange` + 幂等同步 + 多触发源；仍不可靠则调起时销毁重建窗口 |
| 3 | "恢复草稿后继续输入中文"是否可用（Windows WebView2 有已有文本时阻塞 CJK 输入的公开问题） | 仅使用普通 `<textarea>`，禁用 contenteditable 富文本方案 |
| 4 | 默认快捷键在两平台的实际占用情况 | 提供候选键与一键换键；注册失败给可见提示 |
| 5 | macOS 自启插件是否弹出系统授权、行为是否符合预期 | 若体验过差，评估改用原生机制 |
| 6 | 草稿写入应采用的持久性等级（`synchronous` 取值）与自动保存时间参数 | 依据实测的写入次数、输入延迟、崩溃丢失窗口三者取舍 |
| 7 | 打包后（而非 dev 模式）的表现是否与开发期一致 | — |

阶段 2 才需要验证：`tauri-plugin-sql` 下 FTS5 与 trigram tokenizer 是否可用（不可用则维持子串匹配）；数据库索引与备份方式。
阶段 3 才需要验证：密钥存储方案（`keyring` crate 成本评估）。
